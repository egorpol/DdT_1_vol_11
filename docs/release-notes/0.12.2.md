# DdT 1, Vol. 11 — 0.12.2 (pre-release)

This is a patch release of the MEI edition of *Dietrich Buxtehudes Instrumentalwerke* (Denkmäler deutscher Tonkunst, first series, vol. 11, ed. Carl Stiehl, 1903). It adds one editorial accidental in Op. II/7, gives two annotations in Op. II/2 their category label and adds a record of the work reviews of October 2026. It has the same 17 works, and apart from these changes and the header metadata every file is as in 0.12.1.

**Status: corrected, not finalized**, as for 0.12.0 and 0.12.1. The [0.12.0 release notes](https://github.com/egorpol/DdT_1_vol_11/blob/v0.12.2/docs/release-notes/0.12.0.md) describe the contents, how to use the edition and its known limitations, and all of that holds for 0.12.2, with the annotation counts given below. The [0.12.1 release notes](https://github.com/egorpol/DdT_1_vol_11/blob/v0.12.2/docs/release-notes/0.12.1.md) describe the three duplicate ties removed since 0.12.0. The [1.0 checklist](https://github.com/egorpol/DdT_1_vol_11/blob/v0.12.2/docs/finalization-plan.md) lists what remains before 1.0.

## Changes since 0.12.1

### Op. II/7, m. 26: an editorial natural

On p. 151 DdT prints the B3 of its keyboard realization at beat 4.75 (upper staff, `ntgjyu`) without a sign. The natural that DdT prints on the B3 at beat 3.25, in the same voice, stands on the lower staff. A printed accidental holds for its staff to the barline, so the reading depended on whether that natural follows the voice onto the upper staff: CAMAT 0.2.7, which produced this edition's `@accid.ges` values, carried it along the voice and read B♮3; CAMAT 0.2.10 reads accidentals per printed staff and reads B♭3. At beat 4.75 the viola da gamba has B♮3 with a printed natural, and DdT's figures over the continuo's G3 are 4, then 3(♮). The Op. II print figures the G3 with 4 and a natural (Cembalo partbook, p. 25); it has no realization, so it supports the harmony and does not attest the note.

The note now carries a bracketed editorial natural, `<accid accid="n" func="edit" enclose="brack">` (`accid.edit.ntgjyu`); a sign in square brackets is the edition's, not DdT's. The conjectural-emendation annotation `editorial.clash.op207-m26-b4_75` names DdT's reading and the reason. Verovio draws the sign above the upper staff, and the annotation says that it belongs to this B3. The note sounds B♮3 as in 0.12.1: Verovio 6.3.0's MIDI plays it as B3 in both releases. With the sign, `scripts/regenerate_accid_ges.py --check` finds nothing to change under CAMAT 0.2.7 or 0.2.10, so the reading no longer depends on the CAMAT version. The keyboard realization is DdT's, not Buxtehude's.

### Op. II/2: two annotation labels

The two annotations on the notated meter in Op. II/2, `annot.op2_02.m199-206.meter-encoding` and `annot.op2_02.m207-214.meter-encoding`, carried `type="encoding-note"` and no `@label`. They now read `type="editorial" label="encoding-note"`, as the [editorial policy](https://github.com/egorpol/DdT_1_vol_11/blob/v0.12.2/docs/editorial-policy.md#correction-categories) asks. Their text, targets and IDs are unchanged, and the viewer shows the same category. The work's `revisionDesc` records the change.

The corpus now has 101 editorial annotations, all with a label: 55 conjectural emendations, 13 source-supported emendations, 20 source-reading annotations and 13 encoding notes. The 0.12.0 notes counted 98, with the two meter notes of Op. II/2 apart; the 55th conjectural emendation is the one in Op. II/7 above, which makes 68 emendations in all.

### A record of the work reviews of October 2026

[`docs/render-review-2026-10-18.md`](https://github.com/egorpol/DdT_1_vol_11/blob/v0.12.2/docs/render-review-2026-10-18.md) records the work reviews of 2026-10-18 to 2026-10-20, in which an AI coding agent (OpenAI Codex) reviewed work-level reports and Verovio renderings with the editor. It lists the complete-work commits of those days, describes the print check of 10 works, which asserted Verovio's systems against the page and system starts that the facsimile zones give, says what was checked in each work and names the record's limits. The page was reconstructed in November 2026 from git-ignored run folders and the agent's session log; its folder holds three scripts of the time, for Op. II/5, and their layout audit. It changes no file of the edition.

### Headers

All 17 headers now read `<edition n="0.12.2">`, and each `revisionDesc` has an entry for this release. The last-updated date stays 2026-11-16, as set for 0.12.1.

## Identifiers

No `xml:id` of v0.12.1 is gone, and none names a different element. Two are new, both in Op. II/7, m. 26: `accid.edit.ntgjyu`, the editorial natural inside the note `ntgjyu`, and `editorial.clash.op207-m26-b4_75`, its annotation. Measure IDs, numbers, zones and facsimile links match v0.12.1 in all 17 works. The [encoding profile](https://github.com/egorpol/DdT_1_vol_11/blob/v0.12.2/docs/mei-encoding-profile.md#release-identity-versions-and-citation) treats a compatible correction or metadata fix that preserves event identity as a patch.

## Validation record

The consistency reports and their provenance, [`validation/editorial-reports.json`](https://github.com/egorpol/DdT_1_vol_11/blob/v0.12.2/validation/editorial-reports.json), come from a full run completed 2026-11-16 (06:30 UTC) in review mode, with the software of 0.12.0 and 0.12.1: [CAMAT](https://pypi.org/project/camat/) 0.2.7 from PyPI, Verovio 6.3.0, lxml 6.1.2, saxonche 13.0.0, Python 3.14, the pinned official MEI 5.1 CMN schema and the edition profile `DdT_1_vol_11` 0.1.0.

- All 17 files passed XML and reference checks, RELAX NG, Schematron, resource and image-URL checks, full Verovio rendering and CAMAT event parsing. Their hashes were unchanged after the run.
- The edition's publication rules return **needs-review** for all 17, as expected for unfinalized files. The reports contain 286 rows (276 `warning`, 10 `info`), the rows of 0.12.1 apart from their line numbers; the [0.12.0 release notes](https://github.com/egorpol/DdT_1_vol_11/blob/v0.12.2/docs/release-notes/0.12.0.md#known-limitations) explain them under known limitations.
- The test suites pass (123 Python and 35 JavaScript tests). `scripts/regenerate_accid_ges.py --check` and `scripts/normalize_midi_data.py --check` find nothing to change. `scripts/musical_lint.py` lists 171 suspects, as for 0.12.1.
- For Op. II/7 and Op. II/2, Verovio 6.3.0's MIDI of v0.12.1 and of this release is byte for byte the same, with automatic and with encoded page breaks. In Op. II/7 one rendered page gains the bracketed natural and the annotation's group, and nothing else on any page changes; in Op. II/2 only the two annotations' groups change, by their class name and a label title, and neither is drawn.

The release-mode gate was not applied: it accepts only finalized files with a recorded, hash-bound reviewer sign-off, which this pre-release does not claim.

To rerun the checks on this release:

```sh
pip install -r requirements.txt
python scripts/refresh_editorial_reports.py --network
python scripts/regenerate_accid_ges.py --check
python scripts/normalize_midi_data.py --check
python -m pytest -p no:cacheprovider -q tests
node --test tests/js/*.test.mjs
```

The first command validates each work in turn, as the recorded run did, and rewrites the tracked reports and `validation/editorial-reports.json` in place, so `git diff` shows any change; `--network` adds the image-URL checks. The pinned versions need Python 3.12 or newer, and the checks also need libxml2's `xmllint` on `PATH`. An empty or passing report means only that the automated checks found nothing; it does not establish that every pitch, rhythm or figure matches the source.

## Known limitations

Those of 0.12.0, listed in its [release notes](https://github.com/egorpol/DdT_1_vol_11/blob/v0.12.2/docs/release-notes/0.12.0.md#known-limitations). In particular, no work is finalized, each header's `pubStmt/identifier[@type='URI']` points to the file on `main`, not to this release, and transcription errors can remain: no accuracy figure is claimed for any part of the text.
