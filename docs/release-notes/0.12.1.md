# DdT 1, Vol. 11 — 0.12.1 (pre-release)

This is a patch release of the MEI edition of *Dietrich Buxtehudes Instrumentalwerke* (Denkmäler deutscher Tonkunst, first series, vol. 11, ed. Carl Stiehl, 1903). It corrects three ties that 0.12.0 encoded twice. It has the same 17 works, and apart from those three ties and the header metadata every file is as in 0.12.0.

**Status: corrected, not finalized**, as for 0.12.0. The [0.12.0 release notes](https://github.com/egorpol/DdT_1_vol_11/blob/v0.12.1/docs/release-notes/0.12.0.md) describe the contents, how to use the edition and its known limitations, and all of that holds for 0.12.1. The [1.0 checklist](https://github.com/egorpol/DdT_1_vol_11/blob/v0.12.1/docs/finalization-plan.md) lists what remains before 1.0.

## Changes since 0.12.0

In three bars one tie was encoded twice: two `<tie>` elements joined the same two notes. The second copy is removed. Where it named a staff or a curve direction that the first copy lacked, the tie that remains now names it.

| Work | Bar | Staff | Tie | Removed `xml:id` | Remaining tie |
| --- | ---: | --- | --- | --- | --- |
| App. II (BuxWV 266) | 179 | viola da gamba | F♯2 into m. 180 | `tpyyp5x1` | `sd0qax6` |
| App. III (BuxWV 267) | 58 | keyboard, right hand | D4, beat 1 to beat 2 | `tie.app3.m58.d4` | `f11m0sdf77d` |
| Op. I/6 (BuxWV 257) | 152 | keyboard, right hand | E4 into m. 153 | `q9wrrfk` | `q9vedfk` |

Verovio 6.3.0 drew each second copy exactly over the first, so the pages look the same, and its MIDI is unchanged. Each of the three works records the removal in its `revisionDesc`.

All 17 headers now read `<edition n="0.12.1">`, with the last-updated date 2026-11-16 and a `revisionDesc` entry for this release.

## Identifiers

The [encoding profile](https://github.com/egorpol/DdT_1_vol_11/blob/v0.12.1/docs/mei-encoding-profile.md#event-identity) counts ties among the events whose `xml:id`s persist from release to release. This release removes three tie ids, those of the second copies in the table above. Each removed copy joined the same two notes as the tie that remains, so every tie of 0.12.0 is still in 0.12.1, under the remaining id. The profile's patch rule asks for preserved event identity, and three tie ids are retired here, so this release is an exception to the rule's letter. The profile now names that exception under Event identity. 0.11.0, by contrast, removed two notes and was a minor release.

At v0.12.0 nothing in this repository referred to the three removed ids. Links from outside the repository cannot be checked: a link to one of them should move to the remaining id in the table, or pin v0.12.0.

No other `xml:id` is gone or new, none names a different element, and measure IDs, numbers, zones and facsimile links match v0.12.0 in all 17 works.

## Validation record

The consistency reports and their provenance, [`validation/editorial-reports.json`](https://github.com/egorpol/DdT_1_vol_11/blob/v0.12.1/validation/editorial-reports.json), come from a full run completed 2026-11-15 (23:50 UTC) in review mode, with the software of 0.12.0: [CAMAT](https://pypi.org/project/camat/) 0.2.7 from PyPI, Verovio 6.3.0, lxml 6.1.2, saxonche 13.0.0, Python 3.14, the pinned official MEI 5.1 CMN schema and the edition profile `DdT_1_vol_11` 0.1.0.

- All 17 files passed XML and reference checks, RELAX NG, Schematron, resource and image-URL checks, full Verovio rendering and CAMAT event parsing. Their hashes were unchanged after the run.
- The edition's publication rules return **needs-review** for all 17, as expected for unfinalized files. The reports contain 286 rows (276 `warning`, 10 `info`), the rows of 0.12.0 apart from their line numbers; the [0.12.0 release notes](https://github.com/egorpol/DdT_1_vol_11/blob/v0.12.1/docs/release-notes/0.12.0.md#known-limitations) explain them under known limitations.
- The test suites pass (123 Python and 35 JavaScript tests). `scripts/regenerate_accid_ges.py --check` and `scripts/normalize_midi_data.py --check` find nothing to change. `scripts/musical_lint.py` lists 171 suspects: the 168 of 0.12.0 and the three removed tie ids, which it lists among the ids gone since v0.9.0.
- For the three works with a removed tie, Verovio 6.3.0's MIDI of v0.12.0 and of this release is byte for byte the same, with automatic and with encoded page breaks. Their rendered pages differ only by the removed tie: each was drawn on exactly the path of the tie that remains.

The release-mode gate was not applied: it accepts only finalized files with a recorded, hash-bound reviewer sign-off, which this pre-release does not claim.

To rerun the checks on this release:

```sh
pip install -r requirements.txt
python scripts/refresh_editorial_reports.py --network
python scripts/regenerate_accid_ges.py --check
python scripts/normalize_midi_data.py --check
python -m pytest -p no:cacheprovider -q tests
node --test tests/js/*.test.mjs
```

The first command validates each work in turn, as the recorded run did, and rewrites the tracked reports and `validation/editorial-reports.json` in place, so `git diff` shows any change; `--network` adds the image-URL checks. The pinned versions need Python 3.12 or newer, and the checks also need libxml2's `xmllint` on `PATH`. An empty or passing report means only that the automated checks found nothing; it does not establish that every pitch, rhythm or figure matches the source.

## Known limitations

Those of 0.12.0, listed in its [release notes](https://github.com/egorpol/DdT_1_vol_11/blob/v0.12.1/docs/release-notes/0.12.0.md#known-limitations). In particular, no work is finalized, each header's `pubStmt/identifier[@type='URI']` points to the file on `main`, not to this release, and transcription errors can remain: no accuracy figure is claimed for any part of the text. Cite the release tag (below) for a fixed version.
